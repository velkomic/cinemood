# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If these files do not exist, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Layout

This repo uses a single context:

- `GLOSSARY.md`: domain terms.
- `docs/adr/`: architecture decision records.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## Decision conflicts

Explicitly identify any proposal that contradicts an existing ADR,
and explain why the decision should be reopened.
